# CLAUDE.md

Персональный сайт учёного (Байкин Алексей Николаевич / Aleksei Baikin) на GitHub Pages.
Что и зачем делаем, разделы и требования к ним: см. `INTENT.md`. Перед любой существенной задачей перечитай его.

`DRAFT.MD` - не читай вообще. Это для меня черновик.

## Стек (предложение; менять только после согласования со мной)

- Astro + Tailwind CSS + MDX + Content Collections
- KaTeX для формул, Pagefind для поиска
- Интерактивные графики: Plotly или аналог без тяжёлых зависимостей
- Деплой: GitHub Actions → GitHub Pages. Сайт полностью статический.

## Команды

- `npm install` — зависимости (Node ≥ 22.22).
- `npm run dev` — сервер разработки (http://localhost:4321); поиск в dev-режиме не работает.
- `npm run build` — сборка в `dist/` + индекс поиска Pagefind.
- `npm run preview` — просмотр собранного сайта (с поиском).
- `npm run local` — `build` + `preview`; `npm run stop` — остановить сервер dev/preview (Astro 7 не запускает второй сервер, пока работает первый).
- `npm run check` — `astro check` (типы и шаблоны).
- `npm run validate` — номера телефонов в репозитории и `dist/`, приватные файлы в git, ключи `ru.json`/`en.json`.
- `npm run todo` — пометки `TODO` в данных; общий список — `TODO.md`.
- Деплой: push в `main` → GitHub Actions (`.github/workflows/deploy.yml`: build + validate) → GitHub Pages.

## Жёсткие правила

**Приватность**
- Номер телефона не указывать нигде: ни на страницах, ни в метаданных, ни в коде, ни в данных. Перед завершением каждого шага проверь поиском по репозиторию.
- Репозиторий публичный: всё, что лежит в нём, доступно любому.
- Из `ForCLAUDE/` копируй в `assets/` только то, что явно предназначено для публикации (сертификаты, тезисы, фото, CV). Личные документы не публиковать. Удостоверения и дипломы - по моему согласию. Сомневаешься: спроси.
- `ForCLAUDE/` должна оставаться в `.gitignore`. Файлы из неё не коммить напрямую. Если нужно будет для сайта, то копируй в assets, делай адекватное имя файла и тогда закомитишь уже в assets.
- Если я загружаю сертификат или диплом для выкладки, то спроси меня, нужно ли затирать росписи и номера удостоверений (дипломов) по каждому из них. Если я подтвердил, что надо затереть, то затри соотвествующие части: если исходник в pdf, то нужно сконвертировать в png или jpeg в нормальном качестве, там внести исправления - затереть, а потом обратно в pdf. Это нужно, чтобы нельзя было в pdf воссоздать роспись. Оригинальным документам (до затирания) придумай названия, чтобы их можно было опознать быстро. Положи их отдельно в папку FromClaude/, которую нельзя заливать на git.

**Достоверность данных**
- Не выдумывай факты, даты, DOI, названия журналов, соавторов. Источник истины: резюме в `ForCLAUDE/`, в моих публичных профилях и то, что я скажу в чате.
- Резюме это черновик. Чего не хватает: оставь в данных явную пометку `TODO` и перечисли пробелы в отчёте.
- Машинные переводы аннотаций помечай в данных (`translation: auto`), чтобы я мог их проверить.
- Внешние источники данных о публикациях перечислены в `src/data/publication-sources.yaml` (кнопка «Источники данных» на странице «Публикации»). При обновлении сайта сверяй данные с этими источниками и держи список актуальным, но любые правки данных по итогам сверки вноси только по моей команде: я верифицирую их сам.

**Контент и данные**
- Всё, что я пополняю (публикации, выступления, опыт, проекты, курсы, студенты, достижения, блог), живёт в файлах данных (Markdown/MDX, YAML/JSON, BibTeX). Добавление записи не должно требовать правки компонентов. Я хочу иметь возможность потом вручную вносить правки в контент без переделки движка сайта.
- Каждое текстовое поле двуязычное (`title_ru` / `title_en` или аналог). Страницы для двух языков вручную не дублируй.
- Единый справочник тегов; теги задаю я в данных. Фильтры по тегам должны работать везде, где они указаны в `INTENT.md`, и отражаться в URL.

**Многоязычность (i18n)**
- Языки: русский и английский, отдельные URL (`/ru/...`, `/en/...`), корректные `hreflang` и `<html lang>`.
- Язык по умолчанию определяется по `navigator.language` (на GitHub Pages геолокация по IP недоступна). Ручное переключение приоритетнее и запоминается в localStorage.
- Локализованы интерфейс, контент и метаданные (title, description, OG).

**Дизайн**
- Цвета Возьми палитру из референса 1 https://academic-demo.netlify.app/ для темной и светлой темы
- Акцент только для ссылок и кнопок. Контраст текста не ниже 4,5:1.
- Светлая и тёмная темы (переключатель + системная настройка), адаптивность с приоритетом мобильных.
- Анимации умеренные; обязательно учитывай `prefers-reduced-motion`.
- Относительно Минималистичный стиль: компактные карточки, теги, кнопка Подробнее/View для деталей.

**Встраивание материалов**
- YouTube: `youtube-nocookie.com`, ленивая загрузка.
- PDF: встроенный просмотр + кнопка «Открыть/Скачать» (на мобильных встроенный просмотр работает плохо).
- Формулы LaTeX (KaTeX) должны работать на всех страницах, включая блог.

**Процесс работы**
- Работай шагами по плану из `INTENT.md` (раздел «Порядок работы»). К следующему шагу переходи после моего «ок».
- После каждого шага: запусти сборку, убедись, что ошибок нет, кратко отчитайся (что сделано, что нужно от меня).
- Коммиты небольшие и осмысленные, сообщения на английском.
- Держи `README.md` в актуальном состоянии: запуск локально, как добавить публикацию / выступление / запись блога, как выложить на GitHub Pages.
- Если решишь отступить от стека или схемы данных, сначала предложи и обоснуй.
