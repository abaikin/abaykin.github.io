# abaikin.github.io

Персональный сайт Алексея Николаевича Байкина (RU/EN): https://abaikin.github.io/

Сайт статический: Astro 7 + Tailwind CSS 4, публикуется на GitHub Pages через GitHub Actions.
Список дел, пробелов в данных и решений — в [TODO.md](TODO.md).

## Быстрый старт

Нужен Node.js ≥ 22.22.

```bash
npm install
npm run dev        # http://localhost:4321 — правки видны сразу (поиск в этом режиме не работает)
npm run local      # собрать сайт и открыть его как на GitHub Pages: http://localhost:4321 (поиск работает)
npm run stop       # остановить запущенный сервер (dev или local)
```

**Остановить сервер:** `Ctrl+C` в окне терминала, где он запущен, или `npm run stop` из любого окна.
Если запустить сервер второй раз, не остановив первый, Astro сообщит, что сервер уже работает, — сначала `npm run stop`.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | сервер разработки с автообновлением |
| `npm run build` | сборка сайта в `dist/` + индекс поиска Pagefind |
| `npm run preview` | просмотр уже собранного сайта (поиск работает) |
| `npm run local` | `build` + `preview`: локальная проверка сайта перед публикацией |
| `npm run stop` | остановить сервер `dev` / `preview` (`astro dev stop`, `astro preview stop`) |
| `npm run check` | проверка типов и шаблонов (`astro check`) |
| `npm run validate` | проверки: номера телефонов в файлах и в `dist/`, приватные файлы, словари RU/EN |
| `npm run todo` | список пробелов (`TODO`) в данных |

## Как устроено

- Страницы лежат в `src/pages/[lang]/…`: один файл на страницу, версии `/ru/…` и `/en/…` генерируются из него.
- Корень `/` выбирает язык: сохранённый ручной выбор → язык браузера → английский.
- Всё содержимое — в файлах данных, компоненты править не нужно:
  - `src/data/profile.yaml` — «Обо мне»: имя, должность, биография, почта, профили, CV, «Чем занимаюсь»;
  - `src/data/experience/*.yaml` — «Опыт»: работа, проекты и гранты, образование, дополнительное образование, навыки, достижения;
    `src/content/students/<id>.yaml` — студенты;
  - `src/data/laboratory.yaml` — лаборатория;
  - `src/content/courses/<slug>/meta.yaml` (+ `ru.mdx` / `en.mdx`) — курсы;
  - `src/data/tags.yaml` — справочник тегов (ключ → подписи RU/EN);
  - `src/data/publications.bib` — публикации (один файл BibTeX), `src/data/journals.yaml` — категории ВАК и уровни «Белого списка»,
    `src/data/publication-sources.yaml` — внешние источники данных о публикациях (кнопка «Источники данных»);
  - `src/content/talks/<id>.yaml` — выступления (один файл на доклад), `src/data/conferences.yaml` — серии мероприятий для фильтра;
  - `src/content/projects/<slug>/meta.yaml` (+ `ru.mdx` / `en.mdx`) — проекты;
  - `src/i18n/ru.json`, `src/i18n/en.json` — строки интерфейса.
- Файлы для скачивания (PDF, CV) — в `public/assets/`; фото и картинки — в `src/assets/img/` (Astro их сжимает и подбирает размер).
- Цвета — CSS-переменные в `src/styles/global.css` (палитра Hugo Blox Default), шрифты подключаются в `astro.config.mjs`.

### Двуязычные поля

Поле пишется дважды: `title_ru` и `title_en`. Если одного языка нет, сайт покажет второй.
Машинные переводы помечаются `translation: auto`. Незаполненное значение — `TODO`: на сайте появится пометка «будет добавлено».

Внутри фигурных скобок `{ … }` в YAML запятая разделяет поля, поэтому текст с запятой берите в кавычки:
`{ ru: "МКЭ, МКО", en: "FEM, FVM" }`. Если забыть, сборка остановится с ошибкой.

### Как обновить

- **Фото:** заменить `src/assets/img/profile.jpg` (квадрат от 400×400).
- **CV:** положить PDF в `public/assets/cv/` и указать имя в `profile.yaml` → `cv`. Кнопка появляется, только если файл есть.
- **Проект:** создать папку `src/content/projects/<slug>/` с файлом `meta.yaml` (образец — любой существующий проект), см. раздел «Проекты» ниже.
  Связанные работы: `publications: [ключи из publications.bib]` и `talks: [id выступлений]` — на странице проекта появится их список,
  а у публикации в «Подробнее» — ссылка на проект. Выступления, у которых в `publications` есть работа проекта (тезисы, труды),
  попадают на страницу проекта сами; в `talks` пишите только остальные.
- **Курс:** создать папку `src/content/courses/<slug>/` с файлом `meta.yaml`, см. раздел «Курсы» ниже.
- **Тег:** добавить строку в `src/data/tags.yaml`; ключ латиницей.
- **Выступление:** см. раздел «Выступления» ниже. Записи блога — инструкция появится вместе с разделом.
- **Опыт** (работа, гранты, образование, курсы, навыки, студенты, достижения) — см. раздел «Опыт» ниже.

### Публикации

Все работы — в `src/data/publications.bib`. Страница `/ru/publications/` и скачиваемый `/publications.bib` строятся из него.

**Добавить публикацию:**
1. Скопируйте BibTeX у издателя, в Crossref или eLibrary и вставьте в файл (порядок записей не важен — сайт сортирует по годам).
2. Ключ записи — уникальный латиницей, например `ivanov2026model`: по нему работают ссылки `…/publications/#ключ`.
3. Добавьте `langid = {russian}` или `{english}` — язык оригинала.
4. По желанию: `keywords` (теги), `indexing`, `abstract`, перевод названия и аннотации.
5. `npm run build`: если что-то не так (незакрытая скобка, неизвестный тег, неверный DOI), сборка остановится и укажет строку.

**Типы записей** определяют фильтр «Тип»: `@article` — статьи; `@inproceedings` с `pubtype = {proceedings}` или `{abstract}` — труды и тезисы конференций;
`@patent`, `@software` — патенты и программы для ЭВМ; `@thesis` и прочие — «Прочие».

**Поля сайта** (в скачиваемый BibTeX не попадают):

| Поле | Что значит |
|---|---|
| `keywords` | теги из `src/data/tags.yaml`, через запятую |
| `indexing` | индексация: `wos`, `scopus`, `rinc` (РИНЦ), `rinc-core` (ядро РИНЦ), `rsci` |
| `elibrary` | номер статьи в eLibrary — значки «РИНЦ» и «Ядро РИНЦ» станут ссылками |
| `related`, `relatedtype` | связь с переводной версией (см. ниже) |
| `abstract` | аннотация на языке оригинала; формулы — `$…$` |
| `title_ru` / `title_en`, `abstract_ru` / `abstract_en` | перевод на второй язык; `translation = {auto}` — машинный перевод (на сайте пометка) |
| `author_en`, `journal_en`, `booktitle_en`, `holder_en` | английские варианты для английской страницы и строки APA (иначе — транслитерация) |
| `pubtype` | `proceedings` или `abstract` для `@inproceedings` |
| `holder` | правообладатель (патенты, программы) |
| `note_ru` / `note_en` | примечание в «Подробнее» |
| `author_order = {TODO}` | порядок авторов не уточнён (на сайте пометка) |
| `citation_ru` / `citation_en` | строка цитирования вручную, если автоматическая не подходит |
| `fulltext` | путь к PDF внутри `public/assets/`, если имя файла не `pdf/papers/<ключ>.pdf` |

Знаки `% & _ #` в тексте пишутся как `\% \& \_ \#`. Значение `TODO` — пробел в данных (виден в `npm run todo`).
Комментарии `%` пишутся между записями; символ `@` в них не используйте — BibTeX считает его началом записи.

**Полный текст (PDF):** положите файл в `public/assets/pdf/papers/<ключ>.pdf` — у записи появится кнопка «PDF».
У Elsevier и Springer обычно разрешено выкладывать только авторскую версию (accepted manuscript).

**ВАК и «Белый список»** задаются не у статьи, а у журнала: `src/data/journals.yaml` (журнал находится по `issn` статьи,
если ISSN нет — по названию). Там же записаны источники и даты проверки.

**Строка цитирования** считается автоматически: на русской странице — ГОСТ Р 7.0.5-2008, на английской — APA 7.

**Переводная версия статьи** (например, ПМТФ → Journal of Applied Mechanics and Technical Physics): обе версии — отдельные
записи в `publications.bib`, связь пишется один раз, у перевода:

```bibtex
@article{ivanov2013vortex,               % английская версия
  ...
  related     = {ivanov2013vikhr},       % ключ русского оригинала
  relatedtype = {translationof}
}
```

На странице пара показывается одной записью: на русской — оригинал, на английской — перевод; вторая версия видна строкой
«Переводная версия» / «Оригинал» со своей индексацией, DOI и кнопкой BibTeX. Фильтры и счётчики учитывают обе версии.
Ссылки `…/publications/#ключ` работают для обоих ключей. Если связь удобнее указать у оригинала, пишите там
`related = {ключ перевода}` и `relatedtype = {translationas}`.

**Источники данных** (кнопка «Источники данных» на странице) перечислены в `src/data/publication-sources.yaml`: название сервиса,
ссылка и что из него берётся. При обновлении сайта данные сверяются с этими источниками, но правки по итогам сверки
вносятся только по команде владельца — он проверяет их сам.

### Выступления

Один доклад — один файл `src/content/talks/<id>.yaml`. Имя файла (`<id>`) — латиницей, например `2026-tfg`:
по нему работает ссылка `…/talks/#2026-tfg`. Страница `/ru/talks/` группирует доклады по годам; фильтры — мероприятие,
охват, формат и темы, есть поиск. Образец — любой существующий файл, минимальный вариант:

```yaml
date: 2026-09-08            # день доклада; если известны только даты мероприятия — date и date_end: 2026-09-15
lang: ru                    # язык доклада
title_ru: Название доклада
title_en: Talk title
translation: auto           # перевод названия машинный (на сайте пометка)
conference: tfg             # серия из src/data/conferences.yaml
event_ru: X Всероссийская научная конференция «Теплофизика и физическая гидродинамика» (ТФГ2026)
city_ru: Сочи
status: oral                # plenary | invited | oral | short | poster | TODO
scope: national             # international | national-intl | national | unknown
speaker: true               # true — выступали вы, false — соавтор, TODO — уточнить
publications: [ivanov2026tezisy]   # тезисы, труды или статья из publications.bib
```

| Поле | Что значит |
|---|---|
| `status` | формат: `plenary` — пленарный, `invited` — приглашённый, `oral` — секционный, `short` — короткое сообщение, `poster` — стендовый |
| `scope` | охват: `international` — международная, `national-intl` — всероссийская с международным участием, `national` — всероссийская, `unknown` — не указан |
| `authors`, `authors_en` | авторы списком `- Фамилия, И. О.`; если не указаны — берутся из первой публикации в `publications` |
| `tags` | темы из `src/data/tags.yaml`; если не указаны — берутся из связанных публикаций |
| `event_*`, `city_*`, `session_*` | название выпуска мероприятия, город, секция |
| `url`, `program_url` | сайт мероприятия и программа |
| `abstract_pdf` / `abstract_url`, `abstract_pages` | тезисы: свой PDF в `public/assets/pdf/talks/` (встраивается на страницу) или ссылка на сборник; страницы — `59` или `36–37` |
| `slides_pdf` / `slides_url` | слайды: свой PDF в `public/assets/pdf/talks/` или ссылка |
| `video` | идентификатор ролика YouTube (11 символов из адреса `…watch?v=XXXXXXXXXXX`); ролик загружается с youtube-nocookie.com по нажатию «Видео» |
| `award_ru` / `award_en`, `award_pdf` | награда и сертификат (`pdf/certificates/…`) |
| `note_ru` / `note_en` | примечание в «Подробнее» |

Даты и номера страниц можно писать без кавычек. Новая серия мероприятий — строка в `src/data/conferences.yaml`
(короткое название для фильтра и полное — для подсказки). У тезисов и трудов, указанных в `publications`, на странице
публикаций сама появится кнопка «Доклад».

На телефонах встроенный просмотр PDF не показывается — остаётся кнопка «Открыть / скачать PDF».

### Опыт

Страница `/ru/experience/` собирается из файлов `src/data/experience/` и `src/content/students/`. Записи можно писать
в любом порядке — страница сортирует их по датам (новые выше). Даты — `2019`, `2019-09` или `2019-09-01`, без кавычек.

| Файл | Что в нём |
|---|---|
| `work.yaml` | места работы: должность, организация и подразделение, период (`start`, `end`; без `end` — по настоящее время), `kind` (`part-time` — по совместительству, `internship` — стажировка), зона ответственности `duties_*`, результаты `results_*`, проекты |
| `funding.yaml` | проекты и гранты: фонд, номер, название, период, роль (`leader` — руководитель, `participant` — исполнитель), `publications` — работы с благодарностью гранту |
| `education.yaml` | образование: степень, организация и подразделение, работа и руководитель, аннотация, PDF работы, автореферата и диплома, связанные публикации и выступления |
| `training.yaml` | дополнительное образование: программа, организация, даты, часы, описание, скан документа (`certificate`) |
| `skills.yaml` | навыки — списки `technical` и `management`, каждый навык `{ ru: …, en: … }` |
| `achievements.yaml` | благодарственные письма (`kind: letter`) и награды (`kind: award`): дата, название, кто выдал, скан, связанное выступление (`talk`) или грант (`funding`) |
| `src/content/students/<id>.yaml` | студенты: ФИО, тип работы, год, статус, тема, аннотация, PDF, связанные работы |

Сканы и тексты кладите в `public/assets/pdf/certificates/`, `diplomas/` или `theses/`, а в данных указывайте путь без
`public/assets/`, например `certificate: pdf/certificates/2023-skolkovo-agile-hybrid-pm.pdf`. Под записью появится кнопка:
на компьютере документ откроется прямо на странице, на телефоне — отдельно. Пометка `TODO` видна на сайте как «будет добавлено».

### Проекты

Папка проекта — `src/content/projects/<slug>/`, адрес страницы — `/ru/projects/<slug>/`.

- `meta.yaml` — карточка и страница: название, роль, кратко (`summary_*`), статус (`active` / `completed`), период (`start`, `end`),
  организация (`org_*`, `org_url`), технологии (`technologies`: `C++` или `{ ru: …, en: … }`), ссылки (`links`), обложка (`cover`),
  иллюстрации (`gallery`), видео YouTube (`videos: [{ youtube: <id из 11 символов>, title_ru, date }]`), документы (`documents`:
  PDF внутри `public/assets/` или ссылка), теги, связанные публикации и выступления, место в списке (`order`).
- `ru.mdx`, `en.mdx` — подробный текст «О проекте» (Markdown/MDX: формулы `$…$`, картинки, ссылки). Можно один язык — на странице
  другого языка он покажется с пометкой. Машинный перевод помечается в начале файла: `---`, `translation: auto`, `---`.
- Картинки кладите рядом с `meta.yaml`: `cover: ./cover.png`, `gallery: [{ src: ./screen-1.png, alt_ru: …, caption_ru: … }]`.
- Должности и гранты, у которых в `work.yaml` / `funding.yaml` есть `projects: [<slug>]`, появятся на странице проекта сами.
- Список проектов фильтруется по статусу и темам; фильтры отражаются в адресе (`?status=active&tag=auto-frac`).

### Курсы

Папка курса — `src/content/courses/<slug>/`, адрес — `/ru/courses/<slug>/`.

- `meta.yaml`: название, вид (`kind`: `lectures`, `lectures-practice`, `seminars`, `mini-course`, `continuing-education`), роль,
  где читается (`org_*`, `unit_*`), для кого (`audience_*`), когда (`start`, `end`, `schedule_*`), часы (`hours: 72` или
  `{ lectures: 32, practice: 32 }`), язык (`language: ru` или `en`), соавторы (`co_lecturers_*`), форма контроля (`assessment_*`),
  аннотация (`summary_*`), программа (`lectures`: номер, тема, дата, лектор, видео, слайды и ноутбук — файлы в `public/assets/`,
  код — ссылка; пояснение к программе — `programme_note_*`), видео (`videos`), материалы (`materials`), ссылки, теги, публикации.
- Курс больше не читается — `status: archived` (группа «Курсы прошлых лет»).
- `ru.mdx`, `en.mdx` — подробный текст «О курсе»: аннотация, программа, литература.

### Лаборатория

`src/data/laboratory.yaml`. Пока `status: coming-soon`: показываются название, короткое описание (`short_*`), проекты (`projects`)
и блок «Скоро». Для полной страницы — `status: active` и поля `description_*` (абзацы через пустую строку), `directions`,
`partners`, `links`. `people` — сотрудники; публиковать только с их согласия.

## Деплой

Push в `main` → GitHub Actions (`.github/workflows/deploy.yml`) собирает сайт, запускает `npm run validate` и публикует на GitHub Pages.

Однократная настройка репозитория: Settings → Pages → Build and deployment → Source: **GitHub Actions**.

## Приватность

- Номера телефонов не публикуются нигде: `npm run validate` ищет их по шаблону в репозитории и в собранном сайте, и сборка в CI при находке падает.
- `ForCLAUDE/`, `FromClaude/`, `DRAFT.MD` и `proposal.md` — в `.gitignore`.
- Сканы дипломов и сертификатов публикуются после затирания подписей и номеров по решению владельца (CLAUDE.md); оригиналы до затирания — в `FromClaude/`.
